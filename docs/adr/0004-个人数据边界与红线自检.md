# ADR-0004 个人数据边界与红线自检机制

- 日期：2026-10-13
- 状态：已采纳
- 复查时间：每次新增个人字段后自动复查（冒烟测试即复查）

## 背景

这个应用要开源，但它的数据就是"某个人的身体状况与财务目标"。必须有一条能写进代码、能被自动执行的边界，而不是靠人记得。

## 判定

**属于个人信息，绝不进仓库**

- 体脂 / 体重 / 腰围的当前值与目标值
- 本金、现金流、应急金缺口等一切金额
- 真实姓名、本机绝对路径、API Key

**判定为非识别性，可以留在仓库**（理由：属于学习计划的结构参数，不含身份或财务事实，单独出现无法定位到具体个人）

- CEFR 等级，如 `A2`、`B1`
- 水平描述，如 `高中水平`、`A2 → B1`
- 课程结构参数，如 `26 周`、`18:00–23:00`、`W4/W13/W26`
- 训练处方，如 `1.2×体重`、`5–8 次 × 3–4 组`

**灰区规则**：任何新的"数字 + 单位"值，只要同时出现在个人档案里，默认按个人信息处理；要留在仓库必须显式加入 `tools/neutral-vocabulary.txt` 并说明理由。

## 机制（三层，缺一不可）

1. **数据分层**：真实数字只写 `seed.local.js`（`.gitignore` 忽略）；`seed.js` 是中性模板；`seed.local.example.js` 给开源用户复制。
2. **预览隔离**：`?local=0` 忽略本地覆盖，强制中性模板——仓库里的所有截图都由此出，避免个人数字被"烧进图片"。
3. **自动自检**：`node tools/smoke_test.js` 做两件事：
   - 从 `seed.local.js` **自动派生**个人 token（含数值片段与整条文案指纹），扫描全仓库；新增字段即自动纳入，词表不会过期。
   - 用中性词汇表（`seed.js` + `seed.local.example.js` + `tools/neutral-vocabulary.txt`）做单位数字白名单，抓 `seed.local.js` 之外的漏网值。

## 为什么要第 3 层的两条

只用"个人值清单"会漏：早期版本里 `design/mockup.html` 残留了一条真实的应急金缺口金额，而它从来不在 `seed.local.js` 里，人工词表根本扫不到，测试照样全绿（假通过）。
反过来只用"单位数字白名单"会误伤：中性模板里的 `62kg`、`84cm` 本来就是合法的。
两条一起才既漏不掉、又不误报。

## 实测证据

- 修复前：`FAIL  单位数字都在中性词汇表内  design/mockup.html ← （真实金额）`
- 修复后：`PASS  个人值未进仓库（自动派生 14 个 token）`、`PASS  单位数字都在中性词汇表内`

（本文件本身也受这条规则约束——写这份 ADR 时，引用的那个金额被扫描器抓到，于是改成了不带数字的写法。）
