# ADR-0004 个人数据边界与红线自检机制

- 日期：2026-10-13
- 状态：已采纳
- 复查时间：每次新增个人字段后自动复查（冒烟测试即复查）

## 背景

这个应用要开源，但它的数据就是"某个人的身体状况与财务目标"。必须有一条能写进代码、能被自动执行的边界，而不是靠人记得。

## 判定

**属于个人信息，绝不进仓库**

- 体脂 / 体重 / 腰围的当前值与目标值
- 本金、现金流、应急金缺口等一切金额
- 真实姓名、本机绝对路径、API Key

**判定为非识别性，可以留在仓库**（理由：属于学习计划的结构参数，不含身份或财务事实，单独出现无法定位到具体个人）

- CEFR 等级，如 `A2`、`B1`
- 水平描述，如 `高中水平`、`A2 → B1`
- 课程结构参数，如 `26 周`、`18:00–23:00`、`W4/W13/W26`
- 训练处方，如 `1.2×体重`、`5–8 次 × 3–4 组`

**灰区规则**：任何新的"数字 + 单位"值，只要同时出现在个人档案里，默认按个人信息处理；要留在仓库必须显式加入 `tools/neutral-vocabulary.txt` 并说明理由。

## 机制（三层，缺一不可）

1. **数据分层**：真实数字只写 `seed.local.js`（`.gitignore` 忽略）；`seed.js` 是中性模板；`seed.local.example.js` 给开源用户复制。
2. **预览隔离**：`?local=0` 忽略本地覆盖，强制中性模板——仓库里的所有截图都由此出，避免个人数字被"烧进图片"。
3. **自动自检**：`node tools/smoke_test.js` 做两件事：
   - 从 `seed.local.js` **自动派生**个人 token（含数值片段与整条文案指纹），扫描全仓库；新增字段即自动纳入，词表不会过期。
   - 用中性词汇表（`seed.js` + `seed.local.example.js` + `tools/neutral-vocabulary.txt`）做单位数字白名单，抓 `seed.local.js` 之外的漏网值。

## 为什么要第 3 层的两条

只用"个人值清单"会漏：早期版本里 `design/mockup.html` 残留了一条真实的应急金缺口金额，而它从来不在 `seed.local.js` 里，人工词表根本扫不到，测试照样全绿（假通过）。
反过来只用"单位数字白名单"会误伤：中性模板里的 `62kg`、`84cm` 本来就是合法的。
两条一起才既漏不掉、又不误报。

## 实测证据

- 修复前：`FAIL  单位数字都在中性词汇表内  design/mockup.html ← （真实金额）`
- 修复后：`PASS  个人值未进仓库（自动派生 14 个 token）`、`PASS  单位数字都在中性词汇表内`

（本文件本身也受这条规则约束——写这份 ADR 时，引用的那个金额被扫描器抓到，于是改成了不带数字的写法。）

## 补充一：结构性规则（不靠词表）

第 3 层最初只扫"值"，结果漏掉了 `tools/test_xlsx_import.py` 里硬编码的本机绝对路径与用户名——它既不是 `seed.local.js` 里的值，也不是"数字+单位"。所以补第三条：**结构性规则**。

- 追踪文本文件里不得出现盘符形式的绝对路径（字母加冒号再加分隔符；正则同时排除网址协议那一串）。
- 不得出现类 Unix 的家目录前缀（macOS 与 Linux 各有一种写法；具体字面量见 `tools/smoke_test.js`，本文件刻意不复述）。
- 不得出现本机用户名——**从 `os.homedir()` 现场推导**，所以仓库里既没有个人数据，也没有"该防谁"的线索。
- **零例外**。若将来必须有例外，例外本身要写进本 ADR 并说明理由。

## 补充二：两次自指示例的教训

这条规则绊了两次，两次都是"写规则的文件里，出现了会被规则命中的例子"：

1. 本文件初版引用那个真实金额当证据 → 被自己的扫描器抓到，只能改成不带数字的写法。
2. 路径规则的正则注释里举了一个网址协议的反例（含"字母+冒号+分隔符"的字面）→ 被自己的路径规则抓到。
3. 本文件补充一里写了两种家目录前缀的字面 → 被自己的家目录规则抓到。

结论：给规则写注释或文档时，例子必须改写（用"网址协议那一串""类 Unix 的家目录前缀"这类不含字面的说法）。上面这三段本身就是按这个要求写的。

**固化为约定**：任何自带扫描规则的文件（脚本、正则注释、ADR、README）里，不得写出会被自己规则命中的字面量。这条约定适用于以后新加的所有扫描器，不只是本项目的红线规则。

## 补充三：扫描器证明不了的事

- **二进制图片是双向失效的**：文本规则既会**漏**（真烧进 PNG 的数字看不见），也会**误报**（PNG 压缩字节里可能凑出规则序列——实测 `design/preview-app.png` 就撞过路径规则）。所以显式分层：文本规则只扫文本文件，二进制直接跳过（既不算命中，也不算通过）；同时维护 [`docs/binary-artifacts.txt`](binary-artifacts.txt) 清单，清单里的每个文件在发布前由**作者之外的人**逐张看图。冒烟测试会校验清单与磁盘一致，新增截图忘记登记就 FAIL。
- **被 gitignore 忽略的产物**：`seed.local.js`、临时截图目录不进仓库，`check_all.py` 的总断言也看不到它们。这条边界已显式打印在 check_all 的输出里，避免被误解为"管了全部"。

## 补充四：测试不得有副作用（总断言）

出现过"测试原地改写被追踪文件"的问题：早期版本的导入器测试会把合成样例写回 `data/sample.json`，导致每次跑测试工作区都变脏。现在：

- 测试只写临时目录，再与已提交的样例逐字节比对（顺带检查 LF 行尾）。
- `tools/check_all.py` 跑完两套测试后做**总断言**：对比开跑前后的 `git status --porcelain`，不得出现新增改动。这条同时挡住"测试副作用"与"行尾被改回去"两类问题。
