# ADR-0001 本地优先与数据归属

- 日期：2026-10-13
- 状态：已采纳
- 复查时间：M4 发布前

## 背景

打卡数据包含体重、体脂、腰围、资产与现金流这类敏感个人数据；使用者只有一个人，且应用要开源。

## 选项

- **A 云同步**：账号体系 + 后端存储，多端实时同步。
- **B 纯本地**：数据存浏览器 localStorage，通过 JSON 导出/导入搬运。
- **C 本地为主 + 可选自建同步**：本地优先，用户自己部署一个同步服务。

## 权衡

- A 换来多端实时同步，代价是引入账号体系、后端成本、合规负担与隐私面——为了一个人做一个后端，不划算。
- B 零后端、零账号、离线可用，代价是换设备要手动导出/导入。
- C 是折中，但把维护成本转嫁给用户，v1 不值得。

## 决定

选 **B**。JSON 导出文件是唯一真源，用户随时可以完整拿走自己的数据。界面上必须有导出/导入入口，且导出后再导入必须完全一致（已作为冒烟测试的断言之一）。

## 后果

- 换手机/清浏览器数据会丢数据 → 用"每周日导出一次"的操作习惯兜底，README 明确写出。
- 手机上要重新录入基线 → 用导入备份解决。
